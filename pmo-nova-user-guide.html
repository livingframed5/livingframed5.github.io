1 Getting started

Open pmo-nova-command-center.html in Chrome, Edge, or Firefox. No installation, no libraries — it is fully self-contained and works offline.

The dashboard opens on the Overview & KPIs tab, already populated with the Project Nova baseline so every panel means something on first load. Switch tabs with the numbered pills just below the title: Overview Risk Register RAID Log RACI SteerCo Change Playbook.

2 Layout at a glance

  • Top-left — back to portfolio; top-right — light / dark theme (shared with the whole portfolio).
  • Toolbar — Export JSON, Import JSON, Copy Markdown, Download .md, Print view, and Reset demo data. The green pulse on the right confirms auto-save is live.
  • KPI row — the numbers that matter per tab, recomputed instantly from whatever is in the tables below.
  • Tab bodies — six working surfaces, each a set of editable tables plus add/reset controls.

There is no “Apply” button — every edit saves the moment you make it, and every derived number (RAG status, KPI counts, gate verdict) recomputes automatically.

4 Working the risk register & RAG logic

Each risk carries a Probability and Impact (H / M / L). The RAG status is never typed by hand — it is computed:

  • Red — H×H (both high). Must land on the SteerCo agenda.
  • Amber — H×M or M×H. Owner action plan required.
  • Green — everything else.

Filter the register to Red, Amber, or Green with the chips above the table. Click any column header to sort. The RAG pill in each row updates the instant you change a Probability or Impact dropdown — so you can pressure-test a risk live during a review.

Reading it right: the register is only as honest as the Trigger Metric column. The early-warning dashboard works because each risk names the number you watch weekly — edit those triggers to your real operational metrics (helpdesk spikes, ETL failure rates, milestone slips, training completion %).

Use the filter chips to collapse the log to a single type. The KPI row keeps the four classes honest at a glance. Add entries from the Add a RAID entry form; the ID prefixes itself correctly (R-, I-, A-, D-) and finds the next free number.

6 RACI matrix: one “A” per deliverable

Each cell is a dropdown: A (Accountable) / R (Responsible) / C (Consulted) / I (Informed) / − (not involved). Click a cell to change it — the color follows the letter.

  • Add a role column — type a role (e.g. Internal Audit) and click Add column. Every deliverable row gains a matching cell.
  • Add a deliverable row — type a deliverable and click Add row; all cells start at “−” so you consciously assign them.
  • Remove — click the ✕ in a column header (removes the whole role) or at the end of a row (removes the deliverable). Two-step confirm applies.
Exec note: the whole point of the matrix is that accountability is single-threaded — every deliverable has exactly one A. If a row ends up with two A’s or none, that row will drift. Keep the rule: one A, R for the doers, C/I for the informed.

7 Running the weekly SteerCo

  • Deck template — the fixed 10-slot structure (cover → decisions → status → schedule → early-warning → RAID delta → financials → metrics → next-4-weeks → approvals). Rename slots or rewrite content to match your board’s language.
  • Open decisions — the live decision log with owner, due week, options and recommendation. These become slide 2 and slide 10 of the deck automatically.
  • Standing agenda — the meeting cadence itself, as a reference table.

The operating rule is baked into the template: the deck ships 24h ahead, and the meeting is spent only on the Decision Log, the Early-Warning dashboard and Approvals Requests.

9 Saving, exporting, importing & printing

  • Auto-save: every edit writes to this browser’s localStorage instantly. Close the tab, come back — the program is still there.
  • Export JSON — downloads project-nova-pmo.json containing the entire program state. This is your portable, versionable copy (name it per week: nova-pmo-2026-08-13.json).
  • Import JSON — loads an exported file back in. The dashboard validates the shape before accepting it, so a wrong file won’t corrupt anything.
  • Copy Markdown / Download .md — all 8 artifact sections as clean GitHub-flavored markdown tables, ready to paste into a wiki, PR, or SteerCo pack.
  • Print view — opens a clean, print-styled document (no inputs or controls) and lets you print to PDF for the leadership binder.
  • Reset demo data — restores the full baseline. Confirms first, because it discards your current edits.
Heads-up: auto-saved data lives in this browser only. Another machine or browser will not share it — use Export JSON as your portable copy and your normal program repository (wiki / SharePoint) as the durable home.

10 Suggested weekly workflow

  1. Monday — update the facts: open the Risk Register and RAID tabs. Tick progress, adjust Prob×Impact as things land, update trigger metrics with the real numbers from the weekend report. Add anything that surfaced.
  2. Tuesday — sanity-check the map: glance at Overview (milestones and phases). Anything slid? Move the status and fix the date before anyone asks.
  3. Wednesday — build the deck: the SteerCo tab already holds your open decisions. Add the 1–2 motions you need, then Export JSON (versioned) and Copy Markdown into the deck pack.
  4. Thursday — SteerCo: present only Decision Log, Early-Warning and Approvals. Log outcomes back into the decisions table.
  5. Friday — read the readiness: nudge the change sliders to where the numbers actually are and note the gate verdict in next week’s plan.
