SOAR Framework — User Guide

How to run a deal or program through the stage-gate governance process
Audience: Pursuit Leads, Finance, PMO, Sponsors, Consultants Time to read: ~10 min

How This Framework Works

The SOAR framework is a stage-gate governance system for managed-services deals. Every committed dollar of effort, pricing, or risk must pass a formal gate before it is released. The framework lives in four stages, each guarded by a gate that cannot be skipped:

S1 SCOPE & QUALIFY → G1 → O2 OPPORTUNITY & MODEL → G2 → A3 APPROVE & COMMIT → G3 → R4 REVIEW & RUN → G4 → G5 PROGRAM REVIEW (recurring)

Escalation: any gate that fails, any control marked “Not Met”, or any guardrail breach (e.g., margin below MSL, cost-to-serve above threshold for 2+ months) goes up the escalation ladder in the Escalation Pathways section of the framework — in writing, within 48 hours, with a named owner.

How to Fill the Financial Validation

The most important section for finance review. Everything here must trace to a source document listed in the Documentation Repository (the Source Doc ID column is your audit trail).

  • 4.1 Deal Summary — identity fields. Completing this makes the pack traceable.
  • 4.2 TCV Schedule — break TCV by revenue line. Total must reconcile to the order-booking value; if not, explain in the Reconciliation row.
  • 4.3 Gross Margin — one column for the original deal model, one for the latest forecast, one for actuals to date. Variance is model vs forecast. Pass column should only be ticked when results meet the guardrail (≥ MSL for GM%).
  • 4.4 Cost-to-Serve — labor + third-party + overhead per operating month. The “Cost-to-Serve (% of revenue)” row is a guardrail metric — breaching it for 2+ months triggers escalation.
  • 4.5 Variance Analysis — the “why” behind every gap. Fill one row per driver. Root Cause + Mitigation + Owner + Due date are mandatory for any red/over-target item.
  • Forecast Health Statement — completed by the Finance Controller. Overall assessment drives the gate decision (On plan / Watch / Over target / Red).

Controls & Sign-Off

  • Tick C1–C12 only when the evidence exists. “Not Met” blocks the gate and routes to escalation. Any waiver requires CFO + Compliance approval in writing.
  • The Signature Blocks (5.2) make the gate legally defensible: Finance, Risk/Compliance, Pursuit/Delivery, Sponsor, and PMO certification must all be signed for the gate to pass.

Document Repository

  • D1–D15 are the mandatory artifacts. Tick “Uploaded?” and enter the Doc ID. Missing mandatory docs block the gate.
  • Use 6.2 Repository Notes for any annotations, exceptions, or where-files-live details.

Best Practices for Running a Gate Review

  1. PMO issues the gate pack ≥ 5 business days before the gate date.
  2. Reviewers pre-fill the Financial Validation and Controls checklists before the meeting — the meeting is for decisions, not data entry.
  3. Keep to a 45-minute meeting: status (10), finance deep-dive (15), risks/compliance (10), decision & actions (10).
  4. Decision options are always: Approve / Approve with conditions / Reject & rework / Escalate.
  5. File minutes + signed sign-offs in the repository within 48 hours.

Purpose & Scope

Purpose

This framework standardizes the SOAR stage-gate governance applied to complex enterprise managed services pursuits (bids) and in-flight program reviews. It ensures that every deal and program:

  • Passes clearly defined quality, financial, and compliance gates before resources and commitments are released.
  • Has validated financial status (TCV, gross margin, labor cost, cost-to-serve) supported by verifiable source documentation.
  • Carries documented business controls, compliance attestations, and risk mitigations with accountable owners.
  • Reaches delivery with a fully evidenced hand-off and continues through governed program reviews.

Scope

  • In scope: Managed services pursuits ≥ TCV; all program reviews for active dMPS contracts; financial re-forecasts; change orders; renewals/extensions.
  • Out of scope: Product development releases; non-managed-services T&M work; internal admin projects (governed by ).
