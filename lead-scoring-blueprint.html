AI-Powered Lead Scoring System

Inbound channels · enterprise prospects · dynamic 1–100 score · autonomous routing
Inbound Lead Evaluation Deal Values up to $20M ACV Rules · ML · LLM Hybrid Tier → Rep Routing Closed-Won/Lost Feedback Loop

What it does: intercepts every inbound lead (form, chat, email, event, partner), blends a rule gate, a historical ML model, and an LLM qualitative pass into one dynamic 1–100 score, then routes the lead to the correct tier and sales rep before anyone has to read it.

The point: gut-feel lead triage is inconsistent and slow. This design scores prospects on historical engagement patterns and achievable deal size — capped at $20M — and closes the loop on closed-won/lost outcomes so the weights keep learning.

Feature engineering examples

  • Engagement frequency: events in trailing 7 / 30 / 90 days per event type; reply rate; meeting-booked & demo counts.
  • Recency decay: exp(−Δt/τ) per event type (τ tuned per type — a booked meeting decays slower than an email click).
  • Firmographic fit: headcount – revenue – industry match vs ICP definition; stage & funding band.
  • Deal-size anchors: avg won ACV of accounts in the same industry × size band; closest comparable deal; median cycle length.
  • Behavioral depth: pricing-page visits vs blog-only (intent depth); seniority tier & buying-committee role.
  • Base-rate normalization: channel + UTM medium per lead to correct for source differences.
Design rule: the $20M cap is enforced at the schema on deals.won_amount_acv and mirrored in the value model’s log-then-clip target — no enterprise score is ever distorted by an extreme jumbo deal.

2 Scoring Logic & Model Design

Three tiers reconcile into one number 1–100. No single technique owns the score; each has a guardrail.

Tier A — Rule-based heuristics (fast deterministic gates, < 5ms)

RuleEffect
Disposable / competitor / student domainHard disqualify → score 10, route to Ops/blacklist
Budget below floor or geo outside addressable marketHard disqualify
Bot / spam velocity burstHard disqualify
ICP mismatch (firmographic)−20 dampen
Engagement decay (>60d no touch)−15 dampen
Duplicate / known existing account−10 dampen, merge candidate

Tier B — Historical ML predictor (LightGBM, wellness inference < 50ms)

  • Head 1 — conversion: binary gradient boosting on P(won) from historical features ↔ outcomes. Isotonic-calibrated so 0.70 ≈ 70% — honest probabilities, not just rankings.
  • Head 2 — value: quantile regression on realized ACV, log-then-clip at $20M, yielding P10 / P50 / P90 for sizing distributions (not one guess).
  • Imbalance control: stratified sampling + separate treatment of never-scored leads (censoring — see feedback loop).

Tier C — LLM qualitative analysis (async, rubric-scored)

  • Reads the prospect’s raw message and returns strict JSON: intent (budget_ready / assessing / informational / unclear / not_a_buyer), intent confidence, operational fit, technical maturity, urgency signals, red flags.
  • Guardrails: system prompt declares price band + ICP, temperature ≈ 0, JSON schema enforced, prompt-injections in the message ignored, and the LLM augments — it never alone rejects a gate-passed lead.

Composite score (the dynamic 1–100)

conv    = 45 × calibrated P(won)
value   = 25 × bucket( E[deal_size] )        # <$100k / <$1M / $1M–$5M / $5M+ / max
llm     = 20 × (0.55×operational_fit + 0.25×intent + 0.20×technical_maturity)/100
firmo   = 10 × icp_fit_score

base    = conv + value + llm + firmo
score   = clamp( base × Π(gate_multipliers), 1, 100 )   # rounded integer

Weights are prior means, recalibrated weekly on calibration data (Section 4).

3 Pipeline Integration

 1 INGEST   webhook (form/chat/email/event) → validate → dedupe (email+domain)
 2 ENRICH   firmographic pull, match/create account      (async ≤ 2 s)
 3 GATES    Tier A rules (~5 ms)       no → suppress / route-to-ops
 4 FEATURES assemble feature snapshot (feature store, versioned, as_of)
 5 ML       P(won) + E[value] predict  (< 50 ms)
 6 LLM      enqueue message → async worker → rubric JSON (1–3 s, batched)
 7 SCORE    composite 1–100 + tier
 8 ROUTE    round-robin → owner by territory/segment; SLA timers;
            outbound-reply override → straight to owner
 9 SYNC     update CRM (Score / Tier / Owner / NextStep);
            SDR queue push + Slack/Email alert; schedule follow-up
10 OBSERVE  latency, cost, drift, queue backlog alerts
SLA design: steps 5–6 run async so the webhook returns in <300ms — a provisional score is upserted to CRM immediately and the final composite follows. Feature pipeline is idempotent with as_of_ts for replayable training. A 5% control holdout keeps champion ≠ challenger possible.

Bias controls (designed in from day one): routing-position bias is handled by treating never-scored/suppressed leads as censored (inverse-propensity or an always-scored holdout), and a manual override log feeds human routing corrections back into training.

Success KPIs

  • Calibration: Brier score + calibration slope on rolling ground truth.
  • Ranking: lift curves / AUC@k on routed-converted leads.
  • Business impact: conversion uplift vs the 5% control model, time-to-first-outreach SLA adherence.
  • Efficiency: ML-weight share of composite vs rule-only; LLM token + inference cost per scored lead.
